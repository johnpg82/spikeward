# Testing

`npm test` runs everything inside workerd through `@cloudflare/vitest-pool-workers`, with real
D1 and KV.

- `test/sanitize.test.ts`, `test/cluster.test.ts`, `test/policy.test.ts`: the pure pieces.
- `test/replay.test.ts`: replays a spike fixture through the whole loop (poll, baseline,
  cluster, sanitize, judge, decide, enforce, reconcile). Cloudflare's API and Jev are faked at the
  HTTP boundary, so the tests check the exact rules and list items Spikeward writes and the exact
  bodies it would send to Jev (no raw IPs, no attack strings). It also covers shadow mode, verdict
  caching, the janitor, the kill switch, the rules-only fallback, the hourly cap, and that the
  zone's own rules are left alone.

The fake Jev answers from the same features the real model sees. It exists to test Spikeward's
plumbing and policy, not the model; judge real behavior in shadow mode on your own traffic.

## Fixtures

`test/fixtures/spikes/synthetic-mixed.json` is synthetic, generated by
`node test/fixtures/make-synthetic.mjs`: a content scraper spread across 60 DigitalOcean IPs, a
credential stuffer, a vulnerability scanner sending SQL injection and path traversal probes,
Googlebot, an allowlisted uptime monitor, and a real human burst from residential ISPs.

## Recording a real spike

```sh
CLOUDFLARE_API_TOKEN=... npm run record -- --zone <zone id> --from 2026-09-29T11:41:00Z --minutes 2 --name my-spike
```

The recorder remaps every IP into 10.0.0.0/8 (IPs that shared a /24 still do) and drops query
values, so the fixture is safe to commit. ASNs and user agents are kept because the pipeline
needs them. Review the file before committing anyway. Then add a test in `test/replay.test.ts`
that loads it and asserts which clusters should be challenged, blocked, or left alone; when you
change a threshold or question, those assertions show exactly which clusters flip.
